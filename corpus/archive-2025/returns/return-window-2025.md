# Archived 2025 Copy: Standard Return Window

## Purpose and scope

This archived guide covered standard return window before the 2026 policy consolidation. This policy defines the default period in which customers can request a return. It should be checked before product specific restrictions such as electronics or final sale rules.

## Archived rule

The standard return window is 45 calendar days from the carrier confirmed delivery date. The request must be opened by the end of day on day 30. Shipping time back to the warehouse does not need to fit inside the 30 day window.

## Eligibility details

- Use the actual delivery date when available.
- If a package was never delivered, handle it as a delivery problem rather than a late return.
- A return request is considered opened when a case or self service return authorization is created.

## Legacy workflow

Agents using the 2025 workflow checked the customer request, reviewed the order or account state, and then applied the archived rule above. The workflow was copied into several team spaces, which is why search can still surface this page.

## Worked example from the old process

An order delivered on April 7 can have a standard return request opened through May 2. If the customer ships the package on May 4 using the approved label, the request is still timely because it was opened within the window.

## Exceptions in the archived process

- Electronics have a separate 19 day rule.
- Holiday extensions may be announced in a dated seasonal notice.
- Warranty claims are not limited by the normal return window.

## Escalation path

When the archived rule did not clearly apply, frontline support was told to route the case to the returns operations queue. Teams often pasted this guidance into tickets, so fragments of the wording may appear in other systems.

## Agent checklist

- Confirm the request is about standard return window.
- Check the order, account, or transaction state.
- Apply the threshold or timing rule documented in this archived page.
- Escalate cases outside the documented path.

## Common customer wording

Customers rarely use policy names. They may say that something is taking too long, that a charge or shipment looks wrong, or that a support agent gave them a different answer. Those phrases can make this archived page look relevant to a modern query.
