# Archived 2025 Copy: Electronics Return Rules

## Purpose and scope

This archived guide covered electronics return rules before the 2026 policy consolidation. Electronics have a shorter return window because activated or opened devices can lose resale value. This article applies to headphones, tablets, smart home devices, cameras, and similar products listed as electronics.

## Archived rule

Electronics may be returned within 21 calendar days of delivery. Opened electronics are not returnable for preference changes, but defective electronics can still be returned or replaced during the 14 day period. Unopened electronics can be returned for any standard eligible reason.

## Eligibility details

- The serial number must match the order record.
- Factory accessories should be included.
- A device reported as defective may be tested after arrival.

## Legacy workflow

Agents using the 2025 workflow checked the customer request, reviewed the order or account state, and then applied the archived rule above. The workflow was copied into several team spaces, which is why search can still surface this page.

## Worked example from the old process

A customer opens wireless headphones, uses them for two days, and decides the color is not ideal. That is a preference return and is not eligible because the electronics were opened. If one earbud does not power on, the defective item path applies.

## Exceptions in the archived process

- Carrier damaged electronics should use the damaged item process.
- Manufacturer warranty support may apply after the BrightCart return window.
- Items marked final sale remain subject to the final sale rule except for damage or incorrect shipment.

## Escalation path

When the archived rule did not clearly apply, frontline support was told to route the case to the returns operations queue. Teams often pasted this guidance into tickets, so fragments of the wording may appear in other systems.

## Agent checklist

- Confirm the request is about electronics return rules.
- Check the order, account, or transaction state.
- Apply the threshold or timing rule documented in this archived page.
- Escalate cases outside the documented path.
